fix(keepalive): propagate send failures and enforce canonical message rotations

Correct two state and delivery edge cases that could produce misleading client
results or invalid main-message queues.

Transport failure handling:

* propagate failed Konsole/qdbus delivery attempts from both main and secondary
  scheduler paths instead of returning the successful status of the subsequent
  state checkpoint
* preserve the existing consumed-event behavior by resetting only the relevant
  timer after a transport attempt, including a failed attempt
* continue logging and optionally notifying failed sends before returning the
  transport error
* keep the main message index unchanged when MESSAGE+ENTER delivery fails
* allow manual FIFO/IPC clients and the TUI to receive ERROR rather than an
  incorrect OK response
* preserve automatic scheduler stability by continuing to tolerate and log
  failed automatic events without terminating the daemon loop

Main-message rotation validation:

* add daemon-side validation requiring at least one non-empty regular message
  file in a contiguous 001..N sequence
* reject rotations that start after 001, contain numbering gaps, or contain
  empty numbered slots
* run canonical rotation validation before CREATE or CONFIGURE mutates target or
  persistent profile state
* restrict profile/request/target copies to canonical three-digit message files
  so unrelated directory entries cannot enter an active rotation
* retain literal message handling and existing one-logical-line validation

Regression coverage:

* add profile tests for valid multi-message sequences, missing 001, internal
  numbering gaps, and empty slots
* verify rejected CREATE requests leave no monitored target and do not update the
  global profile
* verify rejected CONFIGURE requests leave both selected-target settings and the
  global profile unchanged
* add scheduler tests proving failed main and secondary transports return failure
  while retaining the intended timer behavior
* verify failed main delivery does not consume the queued message and is logged as
  FAILED
* extend the qdbus fixture with a controllable send-failure mode
* exercise transport failure across a real background daemon, request directory,
  FIFO, response directory, and public client boundary
* assert that the end-to-end failure response is ERROR and that the independent
  target log records the failed manual send

Documentation and project memory:

* document canonical message numbering and mutation-free rejection semantics
* document transport failure reporting, timer reset behavior, and rotation
  preservation
* update architecture, maintenance invariants, testing coverage, and validation
  reports
* record the resolved issues and remaining qualification boundaries under
  .agent/
* update the validated assertion count from 71 to 90

Validation:

* pass Bash syntax validation for all source, script, fixture, and test files
* pass all 12 dependency-free test files and all 90 assertions
* pass function-role comment lint
* pass installer/uninstaller layout simulation
* pass real daemon/FIFO integration with mocked qdbus success and failure paths
* pass systemd-analyze verification for keepalive.socket and keepalive.service
* leave ShellCheck as the only skipped optional stage because it is not installed
